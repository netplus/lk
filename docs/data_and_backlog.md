# 数据字典、容量与缺口

## 已入库

- sources.csv：12份原始财报URL、来源发布日期、印刷页、取证方式；PDF原件经网页截图核对，但文件字节未下载，sha256留空，file_archive=link_only_pdf_bytes_unavailable。
- financials/quarterly.csv：30个公司季度，4项CNY元指标。2023–2025来自各年年报分季度表，属于事后版；2026 Q2/Q3用累计差额，Q3前三项同时与报告单季列核对。
- cumulative_2026.csv：6条报告累计值，支持重算；balance_2026.csv：6条期末资产/归母权益。
- annual_derived.csv：6条年度加总，direct_calculation，不能当成独立第三方验证。
- market/staging_display.csv：两股各19天、2026-10-08至11-03网页显示数据。volume_display保留M原文，非精确股数；复权未知，禁止用于收益/回测。来源链接列保留；11月4日盘中排除。
- quality/issues.csv和coverage.json：缺口、处理方式和门禁。未建空的“已完成全量日线”文件。

金额所有financial字段为人民币元。缺失为空而非0。symbol为字符串必须保留前导零。source_ids多输入用“ | ”连接；source_published_date取所有输入最晚日期，仍不是已核实最早披露时间。未来增加版本追加，不静默覆盖。

## 容量估算（假设，不是已下载量）

假设每年240–250个交易日，两股3年约1440–1500行。原始/前复权/后复权三序列约4320–4500行；每行200–400字节，约0.9–1.8MB。再加一个基准、公司行动、版本和来源，预计核心结构化数据5MB以内，预留10MB足够，不必缩短三年范围。

两公司2023–2026Q3原始定期报告目标约30份：6份年报、8份半年报、16份一/三季报。若年报5–25MB、半年报3–15MB、季报0.2–3MB，则粗估约57–318MB；这只是预算。先用来源目录、必要提取表和校验码，避免把大PDF反复写进Git历史。超过预算再考虑受权原件外置，不先削减结构化数据。当前PDF本地副本数量为0。

## 补齐顺序与验收

P0：全量原始日线+精确量/额+交易日历+复权版本/公司行动+沪深300基准。覆盖率按每股实际应交易日核对停牌，不能拿750估计值当100%标准；每股抽查首尾、每季末、除权和极值日，并记录第二独立来源。

P1：补2023–2025原始Q1/H1/Q3，明确首次公开时间/预告/更正，保留每个vintage；补现金流资本支出、资产负债表净债务、股本和分部，不能仅以本期四指标做估值。

P2：逐项恢复SC6/锂盐/库存/产销历史及统计边界；同矿唯一ID、权益/包销和项目爬坡。按经济重要性完成两公司资产档案，不扩大股票池。

P3：通过门禁后再形成三年价格—成交量—财务—产业对齐图，财报事件表和阶段复盘；先检验事实，不优化买卖阈值。只有必要时补2020–2022少量上一轮周期锚点。
